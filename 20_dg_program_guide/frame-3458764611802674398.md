## Summary
DQ management findings from the 20 companies. Companies ideally address DQ at three levels: core data platform (data contracts, ingestion-stage checks/alerts — rare), data engineers (transformation-stage checks, ideally a certified data layer and semantic metrics layer — jokingly noted as non-existent in practice), and BI team (final cleaning in the reporting layer). Popular tooling: Airflow + Great Expectations, dbt test, custom tools; proprietary: Soda, Ataccama, Monte Carlo; data contracts via custom YAML-driven engines. Key problem: tools exist but processes do not — raw-layer checks (nulls, nightly updates) are common while the transformation/views layer is poorly covered; only 10% of companies monitor SLAs for response and resolution times.

## Objects
- Three-level DQ framework: core platform / data engineers / BI team
- Tooling: Airflow + Great Expectations, dbt test, custom; Soda, Ataccama, Monte Carlo; YAML-driven data contracts
- Problem: "tools without processes"; transformation layer under-covered
- Stat: 10% monitor DQ incident SLAs
