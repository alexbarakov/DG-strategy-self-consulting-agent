## Summary
A "Current Data & Analytics Maturity Map" self-assessment template. Goal: evaluate the current maturity level of an organization's data analytics processes and identify areas for improvement. The map is organized into 7 dimensions with numbered sub-areas, each populated with capability blocks laid out along a maturity progression (Data informed → Data Driven → Data Led). Blocks are color-coded by status: Not applicable for us / Done, working fine / In progress / Not started, to be done / Done but has a lot to improve / Passed stage. A note warns that block order in a section doesn't always mean a level up.

## Objects
- **Dimensions and sub-areas:** 1. Getting value from data (1.1 Integration into business, 1.2 D&A Services efficiency); 2. Analytics services (2.1 Reporting factory, 2.2 Self-Serve, 2.3 Experiments, 2.4 Advanced analytics); 3. Analytics Governance (3.1 Content management, 3.2 Customer development, 3.3 Knowing the data); 4. Data Platform Architecture (4.1 Data Storage, 4.2 Data ingestion and transport, 4.3 Data Transformation, 4.4 Business intelligence, 4.5 ML/DS/AI); 5. Data Governance (5.1 Data Discovery & Cataloging, 5.2 Data Quality system, 5.3 Data Security, 5.4 Roles engagement); 6. Data Team (6.1 People management, 6.2 Data Roles, 6.3 Data team structure, 6.4 Project management); 7. Culture (7.1 Executive leadership, 7.2 Decision-Making, 7.3 Data Culture)
- **Status legend:** Not applicable for us; Done, working fine; In progress; Not started, to be done; Done but has a lot to improve; Passed stage
- **Maturity stages:** Data informed → Data Driven → Data Led
- Example capability blocks per progression:
  - Reporting: Reports on requests → Central BI team, cross-functional reporting → Company-level KPI dashboards → Federated BI / Center of excellence → targeted insight delivery/alerts → Gen-AI BI toolset, NLP, real-time and embedded BI
  - Self-serve: Excel-driven self-service → low-code SSBI tools → SSBI framework (portal, style guides, templates, release checklists, support) → community/learning paths → self-serve data preparation environment
  - Experiments: single ad-hoc A/B testing → structured experimentation framework → integrated experimentation platforms → experimentation ingrained in culture
  - Advanced analytics: single forecasting/regression projects → several ML models in prod → MLOps, feature engineering → ML/AI in all business-critical processes → ML/AI as basis for new business models; AI Strategy
  - Content management: reactionary → usage statistics monitoring → content health SLAs → certification framework → archiving procedure → BI Ops automation / BI governance bots
  - Knowing the data: knowledge distributed across SMEs → pre-catalog wiki docs → glossary layer with business ownership → business metrics tree in glossary/semantic layer → enterprise knowledge graph and business ontology
  - Storage: siloed on-premises → DWH with backup/DR → Data Lake → governed layers / certification → Lakehouse → data fabric / data mesh
  - Ingestion: manual handling → simple pipelines → automated pipelines, scheduled batch → ingestion as a service → real-time streaming, reverse ETL → AI/ML-driven intelligent ingestion
  - Data Quality: custom checks for specific objects → DQ monitoring tool, standards, stewards → critical assets covered by sufficient checks → data contracts, DQ embedded in deployment flow → data observability tools
  - Data Security: "common sense" protection → structured security framework (policies, risk assessment, compliance, trainings) → role/domain-based automated access → end-to-end access management with catalog integration and PII encryption → proactive ML-driven security
  - Roles engagement: "natural" chaotic DG with no driver → ownership/stewardship among data people → business representatives engaged in stewardship → CDO/business sponsorship → DG Center / federated DG model / DG dissolved in processes
  - Team structure: IT department, no dedicated team → "all-in-one" analysts → Central BI team → +PO/BAs → Data & Analytics Center → Data Platform Department → network of data teams in federation; roles: Data Analysts, BI Developer/DWH Engineer, Data Scientists/ML Engineers, CDO/CAO
  - People management: competence matrix → seniority grades assessment → role skill profiles and structured onboarding → goals-driven personal KPIs → data skills in corporate hiring policy → company-wide Data Literacy project
  - Culture: no management focus → leaders advocate operational reporting → leaders sponsor advanced analytics and self-service → leaders with high data/AI literacy as evangelists; decision-making from subjective to objective, challenge culture, data-as-a-product mindset, IT-business collaboration mindset
