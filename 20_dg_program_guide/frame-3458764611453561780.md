## Summary
A facilitated-workshop template for structuring the requirements of a data catalog implementation. Five exercise blocks: (1) Core functions of a data catalog, (2) Primary value of a data catalog, (3) Selection factors, (4) Top challenges in developing a data catalog, (5) Implementation sequence on a timeline with MVP and product release milestones. Each block has brainstorm-and-vote instructions; the canvas comes pre-populated with example stickies covering features (primary/secondary/tertiary), value statements, risks, and a phased rollout plan.

## Objects
- Goal: "structure the requirements for implementing a data catalog by identifying key features, values, selection criteria, potential issues, and priorities"
- **1. Core functions** — Primary features: connectors to various data sources; business glossary; metadata enrichment and storage / documentation storage; report catalog; API for custom integration; bulk labeling and classification operations; column-level data lineage; search by keywords or natural-language queries with recommendations; integrated data ownership/stewardship (role-based model). Secondary: data quality status by objects (DQ tool integration); PII/PD identification (automated, rule-based classification); annotations and certification endorsement; tool customization (custom actions/attributes); data sharing and access requesting workflow; DG adoption reporting. Tertiary: collaboration tools (chat, comment, review, rate assets); metadata generating automation; user impersonation and custom user settings; alerting/subscriptions/dependency triggers; approval flow for object change requests; IDE / SQL-Python query editor
- **2. Primary value** (stickies): reduced time to find and understand data objects = improved time-to-market; increased cross-utilization of data objects incl. certified ones; faster onboarding of data/BI analysts; cleaner data landscape (assets archived, duplication removed); impact/dependency analysis faster; personal data scanned and access audited; improved data quality; data stewardship embedded and perceived clearly; growing data culture; "people enjoy it"
- **3. Selection factors** — brainstorm + vote; example sticky: on-premise
- **4. Top challenges** (stickies): too complex for business users; unable to engage business data stewards; unable to engage data professionals; insufficient descriptions and metadata (due to connector difficulties / lack of management and engagement); documentation becomes outdated; lack of trust in catalog data; fragmentation in the user's Golden Path; glossary as a separate challenge (needs business people with systematic mindset); expensive to develop; lack of features; insufficient integrations; difficult to justify budget; difficult to articulate value to the business
- **5. Implementation** sequence (timeline stickies): domain data structure + catalog integration with metadata systems and scanning config; logic for defining the critical layer; lineage for DWH and key ETL packages; load only essential metadata, set limits; BI reports layer integration; role-based ownership/stewardship model; MVP catalog build and production deployment (data power users); BI layers with business glossary terms; certification scenarios; launch for data professionals; advanced ML-driven classification, data sharing and other modules; lineage for second-priority systems; adoption issues analysis and product CustDev; launch for business experts. Milestones: pilot group of departments → MVP release (limited group of data users) → product release (unlimited data and business users); deployment marker
