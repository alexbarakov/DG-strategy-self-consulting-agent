## Objects

### Image 1 — generation comparison table (3 columns x 5 rows, green = strength, red = weakness)
**1st generation**: (green) syncs automatically with your data warehouse, allowing you to escape the task of updating what is created or deleted; (green) optimised to be deployed on **on-premise storage**; (red) designed for IT teams — business users will have a hard time using these data catalogs; (red) demands high set-up and maintenance efforts; (red) limited support for cloud-based warehouses.

**2nd generation**: (green) syncs automatically with your data warehouse, allowing you to escape the task of updating what is created or deleted; (green) better **contextualisation** of the information; (green) advanced rights management features facilitating **data governance**; (red) the data catalog is still **process-based** — it relies on a data steward in charge of labelling the databases; (red) lack of collaborative features that would foster data teams' productivity.

**3rd generation**: (green) **strength of proposal** — the tool guides and optimizes metadata management; in short, it replaces the data steward; (green) **automated context gathering** — the documentation effort is drastically reduced; (green) **collaboration** at the heart of metadata management, users can build on the work of their peers; (green) **design first** data catalogs, easy to use for business users; (red) **limited support for on-premise storage**.

### Image 2 — "5 trends driving third-gen data catalogs"
1. **The modern data stack** went mainstream, with a full range of unprecedentedly fast, flexible, cloud-native tools.
2. **Data teams are more diverse than ever**, leading to chaos and collaboration overhead.
3. **New vision for data governance** — DG is being reimagined from top-down, centralized rules to bottom-up, decentralized community-led initiatives.
4. **Metadata lake** — as metadata itself becomes big data, the metadata lake has the potential to power infinite use cases like data discovery, lineage, observability, meshes, and more.
5. Passive metadata systems are being scrapped in favor of **active metadata platforms**.

### Image 3 — "new vision for data governance" (three before → after pairs)
- Data governance → "Data and analytics" governance
- Centralized approach → Decentralized, community-led approach
- Afterthought → Part of daily workflows

### Image 4 — "metadata lake" architecture
Top row, "A few of the many use cases": Data Discovery / Metrics Repository / Data Observability / Data Lineage & RCA / Auto-tuned Data Pipelines — all five feed off the central band **METADATA LAKE — "Central store of all metadata"**. Bottom row, "Modern data stack", supplies metadata upward: *Data Ingestion* (Fivetran, Stitch, Singer, Airbyte); *Data Warehouse* (Snowflake, Amazon Redshift) and *Data Lake* (Starburst, Amazon Athena); *Data Transformation* (dbt, Matillion, Apache Airflow, Python); *Business Intelligence* (Looker, Tableau, Mode, ThoughtSpot); a fifth column labelled "Data Science" is cut off at the bottom of the image.

### Image 5 — "active metadata approach" (three properties)
- **Always-on**: rather than waiting for humans to manually enter metadata, it continuously collects metadata from logs, query history, usage stats, etc.
- **Intelligence-driven**: it constantly processes metadata to connect the dots and create intelligence, such as automatically creating lineage by parsing through query logs.
- **Action-oriented**: instead of being passive observers, these systems drive recommendations, generate alerts, and operationalize intelligence in real time.

### Image 6 — "3rd Gen: Programmable bots"
"Like bots on Slack". Two examples given: **column-description recommendation bots** and **regulation & risk-reduction bots**.
