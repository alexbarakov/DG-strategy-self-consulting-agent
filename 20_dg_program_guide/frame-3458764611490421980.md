## Summary
A work-in-progress concept map of a Data Quality Management System, inspired by datamanagement.wiki, with 20 concept cards and 33 labeled directional connectors. The central node is Data Issues (non-fulfilment of data quality requirements), surrounded by processes that identify, prevent, resolve, and track them: Data Profiling identifies issues, Data Quality Rules prevent them, Data Cleansing resolves them, Data Quality Monitoring detects/reports them, an Incident Tracking System tracks them, and Data Lineage investigates root causes. Governance concepts (DQ Policy, Stakeholder Analysis, DQ Objectives) and people/structural concepts (Roles and Responsibilities, CDEs, Data Suppliers/Consumers, Data Delivery Agreement) frame the operational core.

## Objects
- Central: Data Issues (synonyms: anomalies, errors, DQ incidents, defects, nonconformities)
- Process concepts (purple): Data Cleansing, Data Profiling, Data Quality Monitoring, Data Quality Rules, Data Quality Dimensions, Incident Tracking System, Data Lineage, Data Delivery Agreement (DDA), Defining Metadata
- Governance concepts (blue): Data Quality Policy, Stakeholder Analysis, Data Quality Objectives
- Reference concepts (teal): Critical Data Elements (CDEs), Roles and Responsibilities (owners, stewards, consumers, producers, analysts, custodians), Data Suppliers
- Contextual/infrastructure (grey): Data Quality, Data Consumers, Business Rules, Databases and Applications
- 33 labeled connectors ("can be resolved by", "identified by", "can be prevented by", "are input for", "is assigned to", etc.)
