## Summary
Ranked list (most to least common) of the pains/drivers through which DG program approval was discussed in the 20 interviewed companies. The top drivers are analyst-facing: data discovery and TTM of data requests; compliance and M&A standardization rank last. A field quote ("process transformations every quarter, so there's no quiet period for DG projects") is flagged by the author as a negative example — dynamic development is a complexity factor, not a blocker; accepting that logic leads to chaos and ad-hoc data management as data grows.

## Objects
- 1. Simplifying data discovery for analysts (find, understand, assess quality, identify ownership, obtain access)
- 2. Increasing speed of data request processing (TTM)
- 3. Improving quality of critical data
- 4. Consistent reporting and addressing metric discrepancies
- 5. Cross-functional data use (navigation + quality understanding for collaborative use)
- 6. Managing compliance risks
- 7. Standardizing data consolidation (fast integration of acquired companies)
- Quote + critical annotation about "no quiet period for DG"
